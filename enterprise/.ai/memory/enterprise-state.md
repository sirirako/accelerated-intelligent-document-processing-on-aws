### JFrog Cache Warming
- **Status:** Scripts implemented, tested at customer site (Jul 2026)
- **Location:** `enterprise/registry/scripts/` (warm-python.sh, warm-node.sh, warm-python.ps1, warm-node.ps1)
- **Customer JFrog:** Customer's internal Artifactory instance
  - PyPI repos: one remote (proxies pypi.org), multiple local (manually uploaded)
  - npm repos: configured via `.npmrc`
  - FOSS repo: separate local repo for manually-uploaded open source packages (e.g., xlsx tarball)
- **Manifests generated by:** `make dep-manifest` → `dist/manifests/python-packages.txt`, `node-packages.txt`
- **Lessons learned:**
  - JFrog metadata cache causes 404 on newer versions — admin must "Zap Caches" or wait for TTL expiry
  - First-time fetches trigger Xray scanning which can timeout — re-run script after a few hours
  - 401 errors: token may only have access to local repos, not remote repos
  - `SELF_SIGNED_CERT_IN_CHAIN`: corporate TLS inspection — use `strict-ssl=false` or `NODE_EXTRA_CA_CERTS`
  - Python warming should run on Linux (EC2 or WSL) for correct manylinux wheels; on Windows use `-Platform linux` flag
  - PowerShell splatting issue: `"--only-binary=:all:"` must be split as `"--only-binary", ":all:"`
  - Node packages are platform-agnostic — can warm from Windows
  - `xlsx` is NOT on npm registry — it's a direct CDN tarball; must be manually uploaded to JFrog
  - Customer WSL was minimal (no bash, no apt, no pip) — use PowerShell scripts instead
- **Known exceptions:** `xlsx@0.20.0` hosted in customer's FOSS repo (direct tarball, not npm registry)

## Upstream Version Compatibility

- **Current fork:** v0.5.16
- **Tested upgrade to v0.6:** Works for non-VPC and VPC stacks (with caveats below)
- **v0.6 known issues:**
  - `custom:idp_groups` schema constraint: stacks created before the `MaxLength: "2048"`
    constraint was added cannot upgrade in-place (Cognito limitation)
  - `ApiUserPoolDomain` fails with uppercase stack names (Cognito domain must be lowercase)
  - `ArtifactsBucketKmsKeyArn` required when S3 bucket uses KMS encryption
  - Fresh VPC deploys need working NAT for CodeBuild Docker pulls
  - v0.6 replaces AppSync with API Gateway REST API — our `AppSyncVisibility=PRIVATE`
    workaround is no longer needed (use `ApiGatewayVisibility=PRIVATE` instead)
